## 1. Where things stand (TL;DR)
* **Two deployable strategies, both NIFTY weekly options:**
  * **B: expiry-day intraday iron fly.** 09:20 sell ATM CE+PE, buy wings priced ~₹3, 50 % leg SL, trail to cost, ₹3k overall SL,
    exit 15:15. 5 years: PF 1.50, ₹24.7k/yr per lot, max DD ₹24.7k, 64 % winning months.
  * **W: overnight weekly iron fly.** Enter 15:15 three trading days before expiry, wings 3 % beyond ATM, ₹8k weekly stop, exit
    09:20 on expiry morning. 5 years: PF 1.17, ₹28.9k/yr per lot, max DD ₹64k. Daily correlation with B: -0.01.
  * **Recommended on ₹5L: B 2 lots + W 1 lot** -> ₹78.5k/yr (15.7 %), max DD 12.4 %, bootstrap 95 % DD ₹1.33L, 64 % winning months.
    Margins never stack (W exits as B enters).
* **Executors exist for the user's own server** (Upstox OrderApiV3): `execution/run_b.py` (multi-account B), `execution/upstox_weekly.py` (W).
  Both are paper by default and paper-tested; one paper trade of B on 9-Nov-2026 (holiday-shifted expiry) netted +₹1,705.
* **Big negative results (do not re-run blindly):** strictly intraday strategies on non-expiry days (options selling, ORB/momentum
  buying, OI/VIX/IV filters) and intraday NIFTY futures (11 years) do **not** survive realistic costs out of sample.
* **User constraints / preferences:** capital ₹5L (can add broker accounts); prefers smooth equity, low DD, many winning months;
  **NIFTY only** (SENSEX/BANKNIFTY downloads stopped on purpose); deploy on own server (not AlgoTest); **overnight is now accepted**;
  wants honest, backtested strategies with stress tests and unseen-data tests.

## 5. Broker / data APIs
**Upstox (primary):**
* Token: env `UPSTOX_ACCESS_TOKEN` in the "Strategy" cloud environment = **extended token, read-only, valid to 2027-10-09**
  (works for market data, historical, expired instruments, margin calculator; **not** for orders or the funds API, which returns
  401 UDAPI1221). Live orders need a normal daily token (expires 03:30 IST) **and the user's registered static IP**.
  Per-account token files via env `UPSTOX_TOKEN_FILE` (see `etl/upstox_backfill.py: token()`).
* Endpoints used: `/v2/expired-instruments/expiries | option/contract | historical-candle/{key}/1minute/{to}/{from}` (Plus);
  `/v3/historical-candle/{key}/minutes/1/{to}/{from}` (index, VIX, live contracts); `/v3/historical-candle/intraday/{key}/minutes/1`;
  `/v2/option/contract`; `/v2/market-quote/ltp`; `POST /v2/charges/margin`; `/v2/market/holidays[/{date}]`; `/v2/market/status/NSE`;
  `/v3/feed/market-data-feed/authorize` + websocket (MarketDataFeedV3 protobuf vendored in `etl/MarketDataFeedV3_pb2.py`);
  orders `https://api-hft.upstox.com/v3/order/place|modify|cancel`, `/v2/order/details`.
* Quirks: Cloudflare blocks the default Python User-Agent (send one). Rate limits 25/s, 250/min, **1000/30 min**; the backfill
  uses 20/s, 240/min, 960/30 min, so ~10 NIFTY expiries per 30 min. The official Python SDK fails to install (old `uuid` dep);
  we call REST/websocket directly. Market orders are not allowed for API algos (limit orders with a buffer).
**Dhan (secondary, history 2021-2024):** `POST /v2/charts/rollingoption`. Verified quirks (docs are wrong): only accepts
`toDate = fromDate + 1 day` (returns both days); needs header `client-id` (inside the JWT) besides `access-token`; `expiryCode`
0 rejected, 1 = current expiry, 2 = next, 3 = after; strikes ATM±10 near expiry, ±3 otherwise; rolling (strike follows spot each
minute, each row carries the real strike); limits 5 req/s, 100k/day. Token: short-lived (~1 day), user supplies it; keep in
`data/dhan/token.txt` (git-ignored). Data plan valid to 2027-11-06.
**Kaggle:** API token (see CLAUDE.md). **NSE:** VIX daily via the NSE site (older round, `etl/build_vix.py`).

## 6. Cost and execution model (all recent rounds)
* Options: brokerage ₹20/order, **STT 0.15 % on option sells (from 1-Apr-2026)**, NSE 0.03503 %, SEBI, stamp 0.003 % buys, GST 18 %.
  Slippage 0.5 % per fill (min ₹0.10), stops +1 %, stops checked on intrabar high/low (pessimistic), same-bar re-check after a
  stop moves. Lot 65.
* Futures: **STT 0.05 % of sell notional (from 1-Apr-2026, was 0.02 %)**, NSE 0.00173 %, stamp 0.002 %, ~₹962 = 14.8 pts per round
  trip per lot + 1 pt slippage per fill.
* Expiry rules: NIFTY weekly Thursday until Aug-2025, Tuesday from Sep-2025, previous trading day on holidays; settlement on the
  last-30-min average (so 15:29 option prices are not intrinsic-only); 2 % extra ELM on short options on expiry day (from Nov-2024);
  F&O hours extended to 15:40 from Aug-2026 (engines use the 09:15-15:29 grid).

## 7. Backtesting and validation concepts used
* **Pre-declared grids and protocols** written before results (e.g. `research/v14_select.py` committed before the grid finished).
* **Unseen-data tests:** options: select on 2024-01..2026-03, test once on 2021-11..2023-12 (never looked at) and the holdout
  2026-03-25..2026-11; futures: select 2015-2020, test 2021-23 and 2024-26. One-shot holdout of frozen strategies (round 5).
* **Plateau selection** (config + one-parameter neighbours) instead of the single best point; **family-level evaluation**
  (median over all configs sharing a structure) to avoid cherry-picking.
* **Walk-forward** (anchored quarterly, earlier rounds), **PBO via CSCV**, **Deflated Sharpe Ratio**, **bootstrap CIs**.
* **Monte-Carlo drawdown** by block bootstrap of calendar months (median / 95th / 99th percentile).
* **Stress tests:** slippage x2, stops on 1-min close, entry ±3-5 min, wing/stop/overall-SL neighbours, worst overnight gaps.
* **Cost sensitivity:** rerun with zero slippage and zero charges to separate "no edge" from "edge eaten by costs".
* **Cross-instrument check:** NIFTY rules applied unchanged to SENSEX (failed -> NIFTY-specific effect).
* **Data cross-validation** between vendors; **simulator validation** against the Rust engine.
* **Portfolio metrics:** correlation, joint DD, margin overlap, Calmar, Ulcer/UPI, winning months, losing runs.

## 9. Strategies
**Deploy candidates:** B (`STRATEGY_CARD.md`, HTML `reports/strategy_b.html`), W (`STRATEGY_W_CARD.md`), portfolio B2 + W1 on ₹5L.

**Rejected (with evidence, don't redo without a new idea):** intraday short strangles/straddles on non-expiry days; DTE1-2
straddles; ORB / momentum option buying (all days); OI walls, max pain, PCR, OI tilt, VIX switch, IV/RV filters as intraday
signals; calendar spreads; butterflies/Batman/ratios; Williams; ORB directional credit spreads (failed 2026); re-entry after
stops; VIX<12 skip (mild only); naked straddle (fails 2026, 1.7x margin); intraday futures ORB/EMA/momentum-into-close/mean
reversion/gap; ITM-option futures substitute; NIFTY fly on SENSEX.

**Potential setups not yet fully explored (ideas for the next session):**
1. **W refinements, judged at family level:** entry 2 vs 3 vs 4 days, wing 2.5-4 %, weekly stop as % of credit, exit on
   expiry-1 close; gap hedges (e.g. small far OTM long strangle overnight); skipping event weeks (budget, RBI, elections, US CPI).
2. **Cheaper execution:** limit orders at mid via the bid/ask recorder data; if slippage halves, re-test intraday futures trend
   (gross PF 1.15-1.29) and B at higher lots.
3. **Positional weekly with next-week hedge (diagonals)** using rank-1 data (Dhan W2 ATM±3 + Upstox next-week chains).
4. **Monthly expiry trades** (Zenodo 2017-2020 + Upstox monthlies) as a separate low-frequency sleeve.
5. **SENSEX/BANKNIFTY** only if the user re-enables them (data partially downloaded).
6. Regime filters for W from features (IV rank, VIX change, PCR change) evaluated at family level with the same OOS protocol.
